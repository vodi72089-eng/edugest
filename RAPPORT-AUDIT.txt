2. FAILLES DE SÉCURITÉ — 26 TESTS PASS, 5 FAILLES PROUVÉES → TOUS CORRIGÉS
===============================================================================
F1 🔴 CRITIQUE (CORRIGÉ + RE-TESTÉ)
    GET /api/medical/visits : un PARENT lisait les visites infirmières de
    TOUS les élèves (motifs, traitements, téléphone des parents).
    Correctif : staff médical/administration uniquement ; le PARENT ne voit
    plus que SES enfants (filtre parentId). Preuve : 1 visite en base,
    le parent en voit désormais 0 (elle appartient à un autre enfant).

F2 🟠 MOYEN (CORRIGÉ + RE-TESTÉ)
    GET /api/schools était 100% public et exposait TOUTES les colonnes
    (tokens WhatsApp Meta, endpoints perso, abonnement, contacts).
    Correctif : annuaire public limité aux champs publics ; champs
    d'administration réservés aux appelants authentifiés.
    Preuve : la réponse publique ne contient plus « whatsappMetaToken ».

F3 🟠 LOGIQUE (CORRIGÉ + RE-TESTÉ)
    Le Super Admin ne pouvait créer AUCUN compte (wildcard '*' mal traité :
    '*'.includes('CASHIER') = false → 403 sur tous les rôles).
    Correctif : wildcard traité avant le includes.
    Preuve : POST /api/users par SAG → 201 (création CASHIER réussie).

F4 🟡 MINEUR (CORRIGÉ + RE-TESTÉ)
    /api/auth répondait 500 + détail interne sur payload malformé.
    Correctif : 400 générique. Preuve : JSON cassé → 400 ; type invalide → 400.

F5 🟡 MINEUR (CORRIGÉ + RE-TESTÉ)
    Aucune limite de longueur sur les communications (10 000 caractères
    acceptés). Correctif : titre ≤ 200, contenu ≤ 5 000 → 400 sinon. Testé.
